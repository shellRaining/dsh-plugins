# 质量与验证

## 测试权限

agent 不得自行新增或改写测试。此限制同样适用于主 agent、子 agent、临时测试脚本、测试夹具、快照和为了验证当前实现而临时拼出的断言代码。不得以委派、换文件名或在命令行内嵌测试的方式绕过。

允许运行类型检查、构建、已有静态检查和手动页面验证。需要新增测试或修改已有用例时，先向用户说明要保护的行为、当前缺口和变更范围，取得明确授权后再动手。任务要求实现功能或修复问题，本身不等于授权修改测试。

仓库当前不保留测试套件，没有可删除或弱化的断言；需要质量保障时按“实际页面验证”一节手动验证。

## 验证顺序

单包开发先运行该包的类型检查和构建。交付前在根目录依次执行：

```sh
pnpm typecheck
pnpm build
```

`pnpm typecheck` 检查各包的类型，`pnpm build` 生成实际入口和客户端 bundle。仓库当前不含自动化测试套件，也没有 `pnpm test` 命令。

当前仓库没有统一 lint / format 命令，不要在交付说明里声称通过了未配置的检查。构建成功只说明静态产物可生成，类型检查和构建都不等于浏览器交互已验证。

收尾用 `git diff --check` 检查空白错误，审查源码、manifest、lockfile 和生成产物是否对应。交付说明列出运行过的命令、结果以及未验证的范围；检查失败不能写成全部完成。

## 实际页面验证

涉及客户端加载、宿主接口、样式或交互时，优先复用用户已经运行的 DSH Web GUI，确认插件确实从本次构建目录加载。不能拿新开的独立 Vite 页面代替 DSH 注入环境。

只在同一宿主 checkout 的 `pnpm run dev:web` 正在重建客户端 bundle 时，才可以依赖 client-plugin HMR 接收更新；否则先完成相应构建再刷新现有页面。不要未经确认承诺热更新，不要擅自改用户 profile 或另起替代服务。

按改动验证插件启停、主要交互、会话切换和清理行为；涉及视觉时检查明暗主题，涉及本地化时检查中英文。优先手动验证，不因缺少自动化覆盖自行编写测试。

没有页面控制能力、加载权限或合适环境时，明确写出未完成运行时验证，不把类型检查、构建或结构测试当成页面验证的替代。
